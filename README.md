# WU Phone

Браузерна гра «зіпсований телефон із малюнками» для спільних дзвінків WU. Один файл `index.html`, синхронізація через Firebase Realtime Database, хостинг на GitHub Pages. Сервер і збирання не потрібні.

- `index.html` — гра **WU Phone** (HTML + CSS + JS).
- `mem.html` — гра **Мемологія**: підбираємо найкращий мем до ситуації.
- `memes/` — картинки для Мемології (`01.jpg`, `02.jpg`, …).
- `avatars/` — персонажі гравців (`01.svg` … `40.svg`), спільні для обох ігор.
- `database.rules.json` — правила безпеки для бази (спільні для обох ігор).
- `README.md` — ця інструкція.

Налаштування займає 10–15 хвилин і робиться один раз.

---

## 1. Створи проєкт Firebase

1. Відкрий <https://console.firebase.google.com> і увійди з Google-акаунтом.
2. Натисни **Add project** (Створити проєкт), назви його, наприклад, `wu-phone`.
3. Google Analytics можна вимкнути — вона не потрібна.
4. Тариф залишається безкоштовним (**Spark**), картку прив’язувати не треба.

## 2. Увімкни Realtime Database

1. У меню ліворуч: **Build → Realtime Database → Create Database**.
2. Обери регіон (для України найближчий — `europe-west1`).
3. Режим — **Start in locked mode**.
4. Відкрий вкладку **Rules**, видали все, що там є, встав вміст файлу `database.rules.json` і натисни **Publish**.

> Потрібна саме **Realtime Database**, а не Firestore — це різні продукти.

## 3. Увімкни анонімний вхід

Правила пускають у базу лише авторизованих гравців, тому кожен браузер непомітно отримує анонімний акаунт. Нічого вводити гравцям не доведеться.

1. **Build → Authentication → Get started**.
2. Вкладка **Sign-in method → Anonymous → Enable → Save**.

## 4. Встав конфіг у `index.html`

1. Натисни на шестерню біля **Project Overview → Project settings**.
2. Унизу, в блоці **Your apps**, натисни іконку **`</>`** (Web), дай застосунку будь-яку назву й натисни **Register app**. Firebase Hosting вмикати не треба.
3. Firebase покаже об’єкт `firebaseConfig`. Скопіюй із нього значення.
4. Відкрий `index.html` у будь-якому редакторі, знайди на початку скрипта блок `FIREBASE_CONFIG` і заміни заглушки `PASTE_…`:

```js
const FIREBASE_CONFIG = {
  apiKey: "AIzaSy...",
  authDomain: "wu-phone.firebaseapp.com",
  databaseURL: "https://wu-phone-default-rtdb.europe-west1.firebasedatabase.app",
  projectId: "wu-phone",
  appId: "1:1234567890:web:abcdef123456"
};
```

Якщо рядка `databaseURL` у конфігу немає, скопіюй адресу з верхньої частини сторінки **Realtime Database → Data**.

> Ці ключі не секретні — вони й так видимі кожному, хто відкриє сторінку. Базу захищають правила з кроку 2.

## 5. Залий на GitHub Pages

1. Створи на GitHub новий **публічний** репозиторій, наприклад `wu-phone`.
2. **Add file → Upload files** — завантаж `index.html` (решту файлів теж можна, вони не завадять) і натисни **Commit changes**.
3. **Settings → Pages**: у блоці **Build and deployment** обери **Deploy from a branch**, гілку `main`, теку `/ (root)` і натисни **Save**.
4. За хвилину-дві гра відкриється за адресою `https://<твій-логін>.github.io/wu-phone/`.

## 6. Перевір

Відкрий адресу гри, створи кімнату, а потім відкрий посилання на кімнату в приватному вікні або на телефоні. Якщо другий гравець з’явився в лобі — усе працює.

---

## Як провести гру

1. Ведучий відкриває гру, вводить ім’я, тисне **«Створити кімнату»** і вмикає показ екрана в дзвінку.
2. Тисне **«Скопіювати посилання»** і кидає його в чат. Гравці заходять зі своїх пристроїв, вводять ім’я та обирають аватар.
3. Коли всі в лобі, ведучий за потреби міняє налаштування (час на текст і на малюнок, максимум раундів, чи грає він сам) і тисне **«Почати»**.
4. Раунди йдуть самі: фраза → малюнок → опис → малюнок → … Раундів стільки ж, скільки гравців, але не більше за встановлений максимум.
5. Наприкінці відкривається альбом. Ведучий гортає його кнопками **«Далі»** і **«Назад»** (або стрілками на клавіатурі), а в усіх на екранах показується те саме. Коли ланцюжок показано до кінця, його можна зберегти картинкою.
6. Під час альбому всі можуть тиснути реакції (😂 🔥 😱 …) — вони летять по екрану в усіх, зокрема на показі екрана ведучого. Кнопка **⭐** біля малюнка — голос за найкращий малюнок, **▶** — повтор того, як його малювали.
7. Після альбому ведучий тисне **«Голосування»**: усі за 30 секунд обирають найсмішніший ланцюжок, і відкриваються **«Результати»** — трійка ланцюжків і найкращий малюнок за зірочками.
8. **«Нова гра»** повертає всіх у лобі з тим самим складом.

### Важливо знати

- Раунди перемикає браузер ведучого. Якщо він оновив сторінку — гра продовжиться, щойно вона завантажиться. Якщо ведучий зник більш ніж на 12 секунд, роль ведучого автоматично переходить до гравця, який зайшов у кімнату найраніше; він побачить повідомлення «Тепер ти ведучий 👑».
- Якщо гравець оновив сторінку, він повертається на те саме місце, а чернетка ходу зберігається. Перевіряй лише, що він відкрив гру в тому самому браузері.
- Якщо гравець відключився, його хід заповнюється заглушкою «🙈 гравець пропустив хід», і гра йде далі.
- Хто зайшов після початку гри, спостерігає й приєднується в наступній.
- Безкоштовний тариф Firebase дозволяє **100 одночасних підключень**. Одна відкрита вкладка — одне підключення, тож на 40 гравців запасу достатньо.
- Кімнати, старші за 24 години, видаляються автоматично, коли хтось створює нову.

## Мемологія

Відкривається кнопкою **«🃏 Грати в Мемологію»** на стартовому екрані або напряму за адресою `…/mem.html`. Налаштування Firebase те саме; потрібні лише актуальні правила з `database.rules.json` (крок 2).

1. Ведучий створює стіл і кидає посилання в чат. Гравці сідають за стіл зі своїх пристроїв.
2. Ведучий тисне **«Роздати карти»** — кожен отримує 6 мемів.
3. Гравці сидять довкола овального столу, ситуація — на верхньому бортику. Кожен обирає мем зі своєї руки і тисне **«Кинути на стіл»**: карта вилітає від гравця, на секунду показується крупним планом у центрі й лягає перед ним лицем догори — сміятися можна одразу.
4. Коли всі кинули (або вийшов час — тоді летить обраний чи випадковий мем), карти вишиковуються в сітку з іменами. Усі голосують за найвлучніший мем клацанням по карті; за свій — не можна.
5. Кожен голос — один бал. Після підсумку раунду гравці добирають по карті, і починається наступний.
6. Після останнього раунду — фінал із рейтингом. **«Нова гра»** повертає всіх у лобі.

Що можна змінити в `mem.html` (усе на початку скрипта):

| Що | Де |
| --- | --- |
| Список ситуацій | масив `SITUATIONS` — по одній у рядку, додавай свої |
| Кількість карт на руці, час підсумку | `HAND`, `SCORE_SEC` |
| Раунди й таймери за замовчуванням | `DEFAULTS` |
| Усі написи | об’єкт `T` |

**Як додати меми:** поклади нові картинки в теку `memes/` з наступними номерами (`120.jpg`, `121.jpg`, …; JPEG, бажано до 640 px по довшій стороні) і збільш число `MEME_COUNT` у `mem.html`.

Ситуації не повторюються від гри до гри, доки не закінчиться весь список: використані пам’ятає браузер ведучого.

## Як змінити тексти, фрази й налаштування

Усе зібрано на початку скрипта в `index.html`:

| Що | Де |
| --- | --- |
| Конфіг Firebase | `FIREBASE_CONFIG` |
| Час раундів і максимум раундів за замовчуванням | `DEFAULTS` |
| Усі написи, кнопки, підказки й помилки | об’єкт `T` |
| Банк фраз для кнопки «Немає ідей» | масив `PHRASES` |
| Персонажі й кольори аватарів | тека `avatars/` + `AVATAR_COUNT`, `AVATAR_COLORS` |
| Кольори й товщини пензля | `PALETTE`, `BRUSHES` |
| Набір реакцій і час на голосування | `REACTIONS`, `VOTE_SEC` |

Якщо міняєш межі налаштувань у `LIMITS`, зміни ті самі числа в `database.rules.json` і опублікуй правила ще раз.

## Якщо щось не працює

| Симптом | Що перевірити |
| --- | --- |
| Екран «Потрібно налаштувати Firebase» | У `FIREBASE_CONFIG` залишилися заглушки `PASTE_…` |
| «Не вдалося підключитися» | Не ввімкнено анонімний вхід (крок 3) або помилка в конфігу |
| «Не вдалося створити кімнату» | Не опубліковано правила (крок 2) або неправильний `databaseURL` |
| «Кімнату не знайдено» | Помилка в коді або кімнаті вже понад 24 години |
| Не працюють реакції, зірочки чи голосування | У Firebase опубліковано стару версію правил — встав актуальний `database.rules.json` (крок 2) |
| Гра «зависла» на раунді | Зачекай 12–15 секунд: якщо ведучий зник, його роль перейде до іншого гравця |
| На GitHub Pages стара версія | Зачекай хвилину й онови сторінку через Ctrl+Shift+R |

Подробиці помилок видно в консолі браузера (F12 → Console).
